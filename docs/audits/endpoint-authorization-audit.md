## Auth primitive — assessment: CORRECT

`services/auth.py::get_verified_user_id` fails closed. Verified properties:

- Returns **503** when `NEXTAUTH_SECRET` is unset — it does not fall open.
- `AUTH_DISABLED` is accepted as an env var but **deliberately not implemented**;
  it logs and JWT verification still runs. This is the right call.
- HS256 via PyJWT (python-jose removed for GHSA-cjwg-qfpm-7377).
- Rejects tokens with no `sub`/`id` claim.

## CRITICAL FINDING — rate limits were inert on 11 endpoints

**Status: FIXED in this PR.**

`main.py` stacked decorators in the wrong order:

```python
@limiter.limit("30/minute")   # applied to a function nobody sees
@app.get("/api/info")         # runs first, registers the UNDECORATED function
async def get_video_info(...):
```

`@app.get` registers whatever it receives. As the inner decorator it captured
the raw function; slowapi's wrapper was then applied to a name the router
never references.

Empirically confirmed against slowapi (isolated reproduction, `3/minute`):

```
broken order (limiter above route): [200,200,200,200,200,200] -> 429 seen: False
correct order (route above limiter): [200,200,200,429,429,429] -> 429 seen: True
```

The global `default_limits=["200/minute"]` did **not** act as a backstop —
an endpoint in the broken order served 8/8 with `default_limits=["5/minute"]`.
These endpoints had **no rate limiting of any kind**.

Confirmed on the real app by inspecting the registered function's code object
(`async_wrapper` = limited, own name = not limited). Before the fix, 11 of 12
limited `main.py` endpoints were unwrapped. Routers (`ai_editor_router`,
`dub_router`, `orchestrator_router`, `pipeline_router`) already used the
correct order and were **never affected**.

Fix: swap the two decorators. Declared limits are unchanged — this restores
the limits the code already intended.

Regression guard: `tests/test_rate_limit_wiring.py` (15 tests) asserts both
statically (no `@limiter.limit` directly above `@app.<verb>` in `main.py`) and
dynamically (every costly path resolves to a slowapi wrapper). 12 of 15 fail
against the pre-fix tree.

### FINDINGS — costly and unauthenticated

All are now rate limited (previously **not limited at all**), but remain open
to anonymous callers.

| Route | Cost | Limit (now live) | Finding |
|---|---|---|---|
| `GET /api/proxy` | yt-dlp resolve + **unbounded byte proxy** through Cloud Run egress | 20/min | **F-1 HIGH** |
| `GET /api/proxy-video` | yt-dlp resolve + range-aware byte proxy | 40/min | **F-1 HIGH** |
| `GET /api/audio` | yt-dlp audio extract, Redis-cached | 20/min | **F-2 MEDIUM** |
| `GET /api/info` | YouTube oEmbed / Data API (quota) | 30/min | **F-3 LOW** |
| `GET /api/stream-info` | manifest resolve, no bytes | 30/min | **F-3 LOW** |
| `POST /api/analytics` | unauthenticated telemetry write | none | **F-4 MEDIUM** |
| `GET /debug/tiers` | leaks extractor tier/circuit internals | none | **F-5 LOW** |

**F-1 (HIGH)** — `/api/proxy` and `/api/proxy-video` stream arbitrary YouTube
bytes through Cloud Run at the platform's egress expense, keyed only by IP.
Egress is billed per GB and these are the largest per-request cost in the
system. Rate limiting is per-IP and trivially defeated by a distributed
caller. **Recommended follow-up (separate PR): require JWT, or issue a
short-lived signed proxy token bound to a project the caller owns.**

**F-4 (MEDIUM)** — `POST /api/analytics` writes to Firestore with no auth.
Capped at `MAX_EVENTS_PER_BATCH` per batch, but unbounded in batch count.
Anonymous callers can inflate Firestore write costs and pollute analytics.

**F-5 (LOW)** — `/debug/tiers` exposes internal extractor state. Should be
moved behind the admin gate.

### Admin surface (17)

All gated by `_require_admin` on `X-Admin-Secret`. `tests/test_admin_fail_closed.py`
verifies it fails closed when the secret is unset (no `None == None` hole).
**The historically-exposed admin secret still requires rotation** — unchanged
by this PR and still open.

## Not addressed here (deliberate scope limit)

F-1 through F-5 are authorization-policy changes that alter who can call
production endpoints. They need a product decision (does the editor call
`/api/proxy` before login?) and belong in their own reviewable PR. This PR
fixes only the defect where the system's *existing, intended* protection was
silently not running.
