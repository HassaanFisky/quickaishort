## Job lifecycle (verified behaviors)

1. API enqueues RQ job with options (+ optional `run_id`).  
2. Worker checks supersede via `render:runid:*`.  
3. Idempotency lock `render:lock:{id}` around GCS upload.  
4. Writes `render:args:*` + processing marker for crash recovery.  
5. `recover_stale_jobs()` on boot for stuck >10min jobs.  
6. `push_result()` updates streams; failures may DLQ `render:dead`.  
7. Progress via Redis pubsub → API → Pusher / WS.  
8. Cancel: `DELETE /api/render/{job_id}` + runid bump.

## RenderManifest

**Intent:** Portable NLE description (tracks, clips, captions, overlays, effects, keyframes).

**Worker behavior:** If `options.render_manifest` present, attempt `compile_manifest_to_ffmpeg`; on failure, fall back / clear (`render_worker.py`).

**Dub Video (ADR-014):** Export options `mute_source_audio` + `dub_audio_uri` are forwarded on `/api/process-video` into `RenderJob`. Optional Manifest fields `muteSourceAudio` / `dubAudioUri` mirror the same contract. Worker mutes source audio and overlays the GCS dub track.

**Tests exist:** `fastapi/tests/test_render_manifest.py`, `test_manifest_renderer.py`, `test_dub_video.py`.

**Studio rule:** New export features should extend Manifest, not invent parallel option bags.

## Output Dimension & Duration Sources of Truth

* **Render Duration Verification**: The verification in `render_worker.py` compares the actual computed `duration_sec` generated by rendering the trimmed `start_sec`-`end_sec` block rather than the `timeline.duration` of the full project (which may be larger than the rendered clip).
* **Tier Resolutions**: `apply_tier_render_policy()` generates dimensions based on the tier. `render_service.py` (`render_video`) dynamically reads `output_width` and `output_height` to crop or scale correctly; they are no longer hardcoded to `1080x1920`.
* **Duration Fallback**: If `duration` fails to parse or is missing/empty string, the fallback will be `videoDuration`. If both are missing/invalid, it reliably fails closed to 0.0 without inventing a 60-second limit. Explicit 0.0 values are handled safely.
* **Success Publishing**: A render cannot publish terminal success unless FFprobe media validation succeeds (`verify_rendered_media` passes checking for video, dimensions, and duration match).

## Verification Scope (E2E Validation)

* E2E tests run without local dependencies (ffmpeg/ffprobe mocked in unit tests). The pipeline correctly evaluates expected vs. returned duration logic without attempting real network fetches in CI tests.
* The explicit conversational editing logic uses `kernel_ack_required` in its response which correctly sets a blocking/pending state before executing project state mutations.
